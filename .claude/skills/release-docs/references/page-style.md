# Page style: rules for editing site pages

Every rule here was learned from a real failure. The sweep or bug that taught it is in brackets.

1. **Edit in place; reuse the page's own components.** Use the `.pipe`/`.pnode` flows, `.ref-table`, `.compare-table`, `.edge-grid`/`.edge` cards, `.callout`, `.tier` and `.codeblock`. Add no CSS. [#108, #127]
2. **Never touch `<head>`** except to resolve an `og-copy` obligation, or to give a page created under `page-missing` its head block. The OG and Twitter tags and `site/og.png` are brand copy. [#117]
3. **A new section** gets a unique `id`, a nav link with `href="#<id>"`, and renumbered `sec-label`s ("04 — …") for every section after it. The render check fails a nav link that has no section. [#127]
4. **`DET` detail strings** are double-quoted JS string literals, rendered with `innerHTML`. They must contain no raw `"`, and `<` and `>` in visible text are written as `&lt;` and `&gt;`. One stray `"` blanks the whole page. [walkthrough 1.2.1]
5. **No bare `<a>` in body copy or table cells.** The pages have no content-link style, so it renders browser-default blue. Name the section instead ("(§04)"). [#127]
6. **The landing grid card's description is `plugin.json`'s description, verbatim.** The "Compose together" card is where release-specific wording goes. [#127]
7. **Frozen example docs (`site/walkthrough/examples/**`) are never edited.** They document a past session as it was. [#117]
8. **Counts appear in several places.** Change the stat, the heading ("Eleven skills"), and the prose ("the five internal steps") together. [#108, #127]
9. **Truth over coverage.** A `covered` declaration must point at text that actually documents the entry. An `at` anchor that merely exists is not coverage.
10. **Every plugin page carries both version badges, in exactly this markup.** `docs-detect.sh` reads only these two forms, so a page that lacks them is never version-checked:
    - nav: `<div class="nav-meta"><span class="dot"></span> PLUGIN · v<version></div>`
    - footer, inside the page's `.foot` block: `<div class="meta"><plugin> · v<version> · MIT · by Apurv Bazari</div>`

    A page generated by walkthrough:document has neither. Its nav kicker is other text, and its only footer is the `wt-credit` provenance line. Set the kicker to `PLUGIN · v<version>`. Then add the `.foot` block (the `← marketplace` and `source on GitHub` links, then the `.meta` line), copied from an existing plugin page along with the five CSS rules that style it (`.foot`, `.foot-links`, `.foot-links a`, `.foot-links a:hover` and `.foot .meta`). Copying those rules verbatim is the one exception to rule 1. Keep the `wt-credit` footer. [release-docs Task 3: a missing badge was silent]
11. **No new horizontal overflow at 500px.** `post-checks.sh` renders each changed page and HEAD's copy of it at 500px. A page whose `scrollWidth` exceeds the viewport fails when HEAD's copy had no overflow, or when the edit made it wider than HEAD's. An overflow that didn't grow is a note in the report, `pre-existing overflow (unchanged: Npx)`, never a failure. The handoff, lens and notify pages already overflow there, because their nav wraps. Don't restructure the nav or add CSS to fix it, and don't make it any wider. Run on its own, `render-check.sh PAGE` has no baseline and fails every overflow; pass `--baseline DIR` (HEAD's copy at `DIR/PAGE`) to judge it the same way. [release-docs Task 5; final review R16]
